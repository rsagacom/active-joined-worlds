# Admin 后台重构方向

## 结论
当前 `admin.html` 的主要问题不是单个颜色或排版，而是产品模型走偏：它把后台做成了“工具/API 目录”，而不是“IM 会话处理工作台”。

重构目标：默认首屏只解决一个问题——管理员现在该处理哪条会话，以及下一步该点什么。复杂工具只放到左侧分类或抽屉里，默认不铺满一屏。

## 产品原则

1. **会话优先**：后台不是治理表单墙，默认进入“待处理会话”。
2. **一次只给一个主动作**：右侧不展示一堆按钮，只展示当前会话最可能需要的动作。
3. **工具按需展开**：居民、房间、公告、安全、世界、系统都作为左侧分类入口，不在首屏同时展开。
4. **隐藏 API 细节**：普通管理 UI 不显示 `POST /v1/...`；API 只进入调试模式或开发文档。
5. **只展示可用能力**：未接后端的功能默认隐藏到“规划中”，不要和可用工具混在一起吓人。
6. **视觉统一**：深色区用浅色字，浅色卡片用深色字；不能再出现低对比度蓝灰叠蓝灰。

## 建议信息架构

### 首屏三块

1. **左侧：会话队列**
   - 搜索
   - 筛选：全部 / 待处理 / 未读 / 私信 / 群聊
   - 会话卡：标题、来源、最后一句、未读数、状态
   - 左侧分类栏可收起，但默认先突出会话队列

2. **中间：当前会话**
   - 聊天消息
   - 输入框
   - 发送 / 快捷回复
   - 当前会话状态：待处理、已读、已回执、发送失败

3. **右侧：当前工具**
   - 只显示当前建议动作
   - 示例：`标记已处理` / `打开居民资料` / `转交安全处理`
   - 一个主按钮 + 最多两个次级按钮
   - “更多工具”进入抽屉，不直接摊开

### 左侧高级分类

- **会话**：待处理、未读、私信、群聊、搜索
- **居民**：查看居民资料、登录状态、封禁/解封、设备记录
- **房间**：房间列表、成员、冻结房间、管理员
- **公告**：发布公告、公告列表、撤回公告
- **安全**：举报、风控记录、封禁、审计日志
- **世界**：城市、线路、镜像源、世界入口
- **系统**：网关状态、同步状态、导出、调试

默认只展开“会话”。其他分类点击后才打开对应抽屉或页面片段。

## 重构执行顺序

### Phase 1：停止工具目录化

- 删除默认首屏中的 API 文案。
- 删除默认首屏中的“高频工具”卡片堆叠。
- 右侧改成 `当前建议动作`：标题、原因、一颗主按钮、一个“更多工具”。
- 修改测试：不再要求默认 UI 出现 API；改为要求默认 UI 不出现 API。

### Phase 2：重建首屏工作台

- 左侧只保留会话队列和可收起分类导航。
- 中间只展示当前会话和发送区。
- 右侧只展示当前会话上下文：居民、房间、状态、建议动作。
- 工具抽屉从右侧滑出，点击分类或“更多工具”才打开。

### Phase 3：高级工具抽屉

- 把居民、房间、公告、安全、世界、系统都迁入抽屉。
- 未接后端的工具放入“规划中”，默认折叠。
- 可用工具显示明确状态：可执行 / 需选择会话 / 需登录 / 后端未接。

### Phase 4：接真实 gateway 状态

- 当前会话、居民、房间、发送状态必须来自 gateway 合同。
- 不允许前端假装成功。
- 发送失败要展示真实错误原因，但首屏文案要产品化，不直接暴露 HTTP 细节。

## 验收标准

1. 打开后台 3 秒内能看懂：当前有几条待处理、当前选中哪条、下一步点什么。
2. 默认首屏不出现 API path。
3. 默认首屏不出现超过 1 个主操作按钮。
4. 未实现功能不和可用功能同级展示。
5. 左侧分类可收起，收起后仍能知道当前所在分类。
6. 深浅底色文字对比清楚，不再出现蓝灰低对比。
7. 测试覆盖：首屏不暴露 API、工具抽屉默认关闭、只有一个主动作、分类切换不破坏会话区域。

## CC 前端任务边界

CC 适合做：
- `admin.html` 结构精简
- `styles.css` admin 视觉重构
- `shell-pages-static.test.mjs` 静态断言同步
- 工具抽屉交互，但只能用 DOM API / `textContent`

不要让 CC 做：
- gateway 合同修改
- 伪造发送成功
- 大量新增后台功能
- 同时改 IM 主路径状态机

## Codex 后端/验收边界

Codex 负责：
- gateway 合同测试
- 真实状态来源检查
- H5 / TUI parity 验收
- 防止前端把不可用功能伪装成可用

## 下一轮建议目标
